# Spec Delta

## MODIFIED Requirements

### Requirement: Отсутствие демонстрационного API

Хост шлюза SHALL публиковать только эндпоинты, относящиеся к функциональности шлюза, включая
health-пробы. Эндпоинты, добавленные генератором проекта, в приложении отсутствуют.

#### Scenario: Обращение к шаблонному эндпоинту

- **WHEN** клиент выполняет `GET /weatherforecast`
- **THEN** хост отвечает `404 Not Found`
- **AND** в приложении нет обработчика, зарегистрированного под этот путь

#### Scenario: Список доступных путей после старта

- **WHEN** приложение запущено с конфигурацией по умолчанию
- **THEN** среди health-путей доступны только liveness- и readiness-пробы
- **AND** шаблонных путей демонстрационного API нет

## ADDED Requirements

### Requirement: Readiness-проба

Хост SHALL предоставлять пробу готовности по пути `GET /health/ready`. Проба SHALL проверять
доступность хранилища и возвращать `200` при успехе и `503` при недоступности зависимости, не
раскрывая параметров подключения и секретов.

#### Scenario: Хранилище доступно

- **WHEN** клиент выполняет `GET /health/ready`, а хранилище отвечает
- **THEN** хост отвечает `200 OK`
- **AND** тело ответа сообщает о готовности без деталей конфигурации

#### Scenario: Хранилище недоступно

- **WHEN** клиент выполняет `GET /health/ready`, а проверка хранилища завершается ошибкой
- **THEN** хост отвечает `503 Service Unavailable`
- **AND** тело ответа не содержит строки подключения и секретов

#### Scenario: Liveness не зависит от readiness

- **WHEN** проверка хранилища завершается ошибкой
- **THEN** `GET /health/live` по-прежнему отвечает `200 OK`
- **AND** liveness не выполняет обращений к хранилищу
