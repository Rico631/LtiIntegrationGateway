# Proposal

## Why

ADR §15.2 требует endpoint состояния канала: наличие ключа секрета, срок действия клиентского
сертификата и последние ошибки. Сейчас таких данных нет: администратор не видит, настроен ли секрет
активной ревизии, не истёк ли клиентский сертификат и какие ошибки недавно возникали при обмене с
внешней системой. ADR §13 отдельно требует отражать срок действия клиентского сертификата в
состоянии канала. Без этого диагностика сбоев выполняется только по журналам БД.

## What Changes

- Появляется управляющая операция `GetChannelHealth` и REST-маршрут
  `GET /v1/channels/{name}/health`.
- Ответ содержит: имя канала, состояние (активная ревизия есть или нет), номер активной ревизии,
  признак настроенного секрета и имя ключа конфигурации (без значения), срок действия клиентского
  сертификата, последние ошибки обмена и время проверки.
- Секрет проверяется для типа авторизации активной ревизии: `none` — секрет не требуется,
  `bearer`/`api_key`/`basic` — значение по ключу должно присутствовать,
  `client_certificate` — материал сертификата должен загружаться и быть действительным.
- Последние ошибки берутся из журналов `OutboundMessageLog` и `InboundMessageLog` по каналу: время,
  направление, код ошибки, HTTP-статус (для исходящих) и исход. Тела сообщений и значения секретов в
  ответ не попадают.
- Неизвестный канал — `404`; канал без активной ревизии — `200` с состоянием
  `NO_ACTIVE_REVISION` и диагностикой.
- Чтение состояния фиксируется в аудите управляющих операций.

Исключено из объёма:

- автоматические проверки живости внешней системы и сетевые пробы — ADR §20 (наблюдаемость);
- метрики, OTel и readiness-проба — открытый вопрос ADR §17, §20;
- изменение состояния канала (включение, отключение, ротация секрета) — существующие срезы;
- проверка отзыва сертификата (OCSP/CRL).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `management-api`: чтение состояния канала (секрет, сертификат, последние ошибки).

## Impact

- `Protos/v1/management_api.proto` — новый RPC и сообщения.
- `Features/Channels` — срез чтения состояния канала.
- `Features/Management` — фасад и маппинг.
- `src/LtiIntegrationGateway.Tests` — тесты состояния, аудита, отсутствия секретов.
- `README.md`, `ARCHITECTURE.md` — описание операции и ограничений.

## Assumptions

- «Последние ошибки» ограничиваются фиксированным числом (5) последних записей по каждому
  направлению; отдельная политика хранения не вводится (ADR §11.2 — бессрочное хранение журналов).
- Для канала без активной ревизии состояние `NO_ACTIVE_REVISION` возвращается со статусом `200`:
  отсутствие активной ревизии — диагностируемое состояние, а не отсутствие канала.
- Имя ключа конфигурации не является секретом (ADR §7.5) и возвращается для диагностики; значение
  не возвращается никогда.

## Risks

- Чтение последних ошибок добавляет запросы к журналам; выборка ограничена индексом по каналу и
  временем и не влияет на приём/отправку сообщений.
- Загрузка сертификата для проверки использует кэш `IChannelCertificateStore`, поэтому не создаёт
  лишних обращений к файлу/окружению.

## Success Criteria

- `GET /v1/channels/{name}/health` возвращает состояние активной ревизии, признак секрета, срок
  сертификата и последние ошибки.
- Значение секрета и тела сообщений в ответе отсутствуют.
- Неизвестный канал — `404`; канал без активной ревизии — `200` с `NO_ACTIVE_REVISION`.
- Чтение состояния фиксируется в аудите.
- `dotnet build` и `dotnet test` проходят; сценарии покрыты тестами.
