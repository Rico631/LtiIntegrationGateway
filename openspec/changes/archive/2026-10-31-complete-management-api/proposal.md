# Proposal

## Why

Все 18 RPC управляющего сервиса уже имеют реализации, но часть поведения не доведена до требований
ADR §15.1 и §15.2: `GetChannel` не пишет аудит; при неизвестном канале операции `UpdateChannelDraft`,
`PublishChannelRevision`, `ActivateChannelRevision` и `RollbackChannelRevision` завершаются `NotFound`
до записи аудита; невалидные настройки в `UpdateContractVersionSettings` возвращают отказ без записи
в аудит. В результате аудит управляющих операций неполон, хотя ADR требует фиксировать все операции,
включая чтение и отказы.

Дополнительно контракт и документация отстали от кода: комментарий `ChannelSettings.auth_type`
утверждает, что `client_certificate` не поддерживается, а README — что управляющий API маршрутов
продуктов не реализован.

## What Changes

- `GetChannel` фиксирует в аудите успешное чтение канала.
- Неизвестный канал в `GetChannel` и в изменяющих операциях (`UpdateChannelDraft`,
  `PublishChannelRevision`, `ActivateChannelRevision`, `RollbackChannelRevision`) возвращает
  `404`/`NotFound` и фиксируется в аудите как отклонённая операция.
- `UpdateContractVersionSettings` фиксирует в аудите отказы валидации, которые обнаруживаются до
  вызова среза (отсутствующие настройки, неизвестный тип авторизации).
- Комментарии `management_api.proto` актуализируются: поддержка `client_certificate`, перечень кодов
  проблем, семантика аудита чтения. Поля, номера и состав RPC не меняются.
- README приводится к фактическому состоянию управляющего API.

Исключено из объёма:

- добавление новых RPC, в том числе «список версий контракта»: состав контракта фиксирован ADR §15.2
  и в этом изменении не расширяется;
- перенос аудита `GetChannelHealth` из среза в фасад: чтение уже фиксируется срезом;
- персональная идентичность администратора (JWT/IdP) — открытый вопрос ADR §20.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `management-api`: аудит чтений и отказов `NotFound` для операций канала; явное поведение при
  неизвестном канале.

## Impact

- `src/LtiIntegrationGateway/Features/Management` — аудит в фасаде и общий помощник поиска канала.
- `src/LtiIntegrationGateway/Protos/v1/management_api.proto` — только комментарии.
- `src/LtiIntegrationGateway.Tests` — тесты аудита чтения, `NotFound` и отказов валидации.
- `README.md` — актуализация раздела управляющего API.

## Assumptions

- Аудит чтения — одна запись на вызов; для `GetChannel` операция называется `GetChannel`, объект —
  имя канала.
- Неудачный поиск канала фиксируется один раз в фасаде; срезы для этих методов аудит не пишут.
- `GetChannelHealth` продолжает писать аудит в срезе; дублирования в фасаде не появляется.

## Risks

- Новые записи аудита увеличивают объём таблицы; срок хранения бессрочный (ADR §11.2), отдельная
  политика не вводится.
- Тесты, которые считают точное число записей аудита, потребуют обновления.

## Success Criteria

- Успешный `GetChannel` оставляет запись аудита с операцией, каналом и результатом.
- `GetChannel` и четыре изменяющие операции по неизвестному каналу возвращают `404`/`NotFound` и
  оставляют запись аудита об отказе.
- `UpdateContractVersionSettings` с отсутствующими настройками или неизвестным типом авторизации
  оставляет запись аудита об отказе.
- Комментарии `management_api.proto` соответствуют коду; README не содержит утверждения о
  нереализованном управляющем API маршрутов продуктов.
- `dotnet build` и `dotnet test` проходят; проверка документации `.proto` из `AGENTS.md` даёт пустой
  вывод.
