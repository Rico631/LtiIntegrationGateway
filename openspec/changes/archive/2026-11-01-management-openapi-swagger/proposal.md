# Proposal

## Why

Управляющий API описан только в `protos/v1/management_api.proto`. Потребителю, который работает через
REST (JSON transcoding), приходится вручную сопоставлять аннотации `google.api.http` с сообщениями, а
проверить вызов можно только внешним инструментом. Публикуемого описания REST-контракта нет.

## What Changes

- Сервис `Management` публикует OpenAPI 3.0-документ управляющего API по `/openapi/management.json` и
  Swagger UI по `/swagger`.
- Документ строится при старте из дескриптора `management_api.proto`, встроенного в сборку `Contracts`:
  пути и HTTP-методы — из аннотаций `google.api.http`, схемы запросов и ответов — из сообщений,
  описания операций, полей и перечислений — из комментариев `.proto` (для этого protoc вызывается с
  записью дескриптора и `source_code_info`).
- Второй источник истины не создаётся: документ и transcoding-маршруты читают один контракт.
- Оба адреса доступны без ключа API; сами управляющие операции продолжают требовать ключ.

## Impact

**Код.** `Contracts` встраивает дескриптор с комментариями (шаг protoc в проекте); `Management`
получает `Infrastructure/Documentation/ManagementOpenApiDocument`, публикацию документа и Swagger UI;
добавляется пакет `Swashbuckle.AspNetCore.SwaggerUI` (только UI, без зависимости от `Microsoft.OpenApi`).

**Контракты.** `protos/v1/management_api.proto` не меняется: документ выводится из него. Версии
публикуемого REST-контракта и gRPC не меняются.

**Безопасность.** Документ и UI раскрывают структуру управляющего API без аутентификации; значения
секретов в контракте отсутствуют (передаются только ключи конфигурации), поэтому новые данные не
раскрываются. Доступ ограничивается сетевой доступностью сервиса управления.

**Альтернатива и причина отказа.** Пакет `Microsoft.AspNetCore.Grpc.Swagger` не используется: он снят с
поддержки («deprecated, has no direct replacement», dotnet/aspnetcore#67134) и зависит от
`Swashbuckle.AspNetCore 6.6.2` → `Microsoft.OpenApi 1.6.14`, тогда как `Core` уже использует
`Microsoft.OpenApi 3.11.0` для чтения входящих OpenAPI-документов. Проверка комбинации `6.6.2` +
`3.11.0` завершается `TypeLoadException` (`Microsoft.OpenApi.Models.OpenApiDocument` отсутствует), то
есть подключение пакета потребовало бы откатить чтение контрактов в `Core` на устаревшую API
`Microsoft.OpenApi`.

## Критерии успеха

- `GET /openapi/management.json` возвращает OpenAPI 3.0 с операцией для каждого rpc, у которого задана
  аннотация `google.api.http`; путь и HTTP-метод совпадают с аннотацией.
- `/swagger` открывается без ключа API и работает с документом.
- Новый rpc с аннотацией появляется в документе после пересборки и запуска без правки кода.
