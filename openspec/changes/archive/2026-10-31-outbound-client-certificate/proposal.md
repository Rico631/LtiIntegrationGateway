# Proposal

## Why

ADR §7.5 перечисляет `client_certificate` среди обязательных типов авторизации исходящего канала,
а §7.7 требует изолировать HTTP-соединения по ключу `(base_url, auth_type, отпечаток сертификата)`.
Сейчас исходящий контур поддерживает только `none`, `bearer`, `api_key` и `basic`: ревизия с
`client_certificate` отклоняется кодом `AUTH_TYPE_UNSUPPORTED`, а все вызовы идут через один
`HttpClientHandler`, поэтому каналы с разными клиентскими сертификатами не могут работать
одновременно. Это блокирует подключение внешних систем, требующих mTLS.

## What Changes

- Канал с типом авторизации `client_certificate` выполняет исходящий вызов с клиентским
  сертификатом из конфигурации: материал сертификата и пароль читаются по ключам конфигурации,
  в базе остаются только тип авторизации и ключ конфигурации (ADR §7.5, §13).
- Отсутствие или непригодность материала сертификата приводит к отказу `SECRET_NOT_CONFIGURED`
  до HTTP-вызова; значение материала и пароля не попадает в результат, журнал, логи и тесты.
- HTTP-обработчики пулируются по ключу `(base_url, auth_type, отпечаток сертификата)`: каналы с
  одинаковым ключом переиспользуют соединения, каналы с разными сертификатами не смешиваются;
  смена ревизии с другим сертификатом приводит к новому обработчику (ADR §7.7).
- Для всех исходящих вызовов: минимальная версия TLS 1.2, автоматические редиректы запрещены,
  серверный сертификат валидируется всегда (ADR §7.7, §8.7, §13).
- Политика повторов, таймауты, классификация ошибок и формат `OutboundResult` не меняются.

Исключено из объёма:

- OAuth2 client credentials — открытый вопрос ADR §20;
- горячая перезагрузка секретов без перезапуска приложения — ограничение ADR §7.4;
- проверка отзыва сертификата (OCSP/CRL), прокси и настройка TLS на уровне ingress;
- отображение срока действия сертификата в состоянии канала — отдельное изменение (ADR §15.2).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `outbound-dispatch`: авторизация исходящего канала поддерживает `client_certificate`; добавляется
  требование изоляции HTTP-соединений по ключу канала.

## Impact

- `src/LtiIntegrationGateway/Features/Outbound` — резолвинг авторизации и выполнение HTTP-вызова.
- `src/LtiIntegrationGateway/Infrastructure` — новый компонент пула обработчиков и загрузка
  материала сертификата.
- `Program.cs` — регистрация компонентов вместо единственного `HttpClientHandler`.
- `src/LtiIntegrationGateway.Tests` — unit- и интеграционные тесты авторизации, пула и отказов.
- `README.md`, `ARCHITECTURE.md` — фактическое описание компонентов после архивации.

## Assumptions

- Материал клиентского сертификата задаётся ключом конфигурации из ревизии канала: значение —
  путь к PFX-файлу либо PFX в base64; пароль читается по ключу `<config_key>:Password`. Формат
  фиксируется в design и документируется в README, поскольку ADR задаёт только требование
  «сертификат и пароль в переменных окружения или файле».
- Смена сертификата вступает в силу после перезапуска приложения: окружение не перечитывается
  в рантайме (ADR §7.4).

## Risks

- Реальный mTLS-сценарий сложно воспроизвести в интеграционном тесте без тестового TLS-сервера;
  часть проверок выполняется на уровне выбора обработчика и подменяемого транспорта.
- Пул обработчиков удерживает соединения по ключу канала; при большом числе ревизий требуется
  ограничение времени жизни обработчика, иначе число соединений растёт.

## Success Criteria

- Канал с `client_certificate` выполняет HTTP-вызов с предъявлением сертификата, а без материала
  сертификата получает `SECRET_NOT_CONFIGURED` и внешняя система не вызывается.
- Два канала с разными сертификатами используют разные обработчики; повторный вызов в рамках
  одного ключа переиспользует обработчик.
- Для исходящего клиента отключены редиректы, минимальная версия TLS — 1.2, проверка серверного
  сертификата не отключается.
- Значения сертификата и пароля отсутствуют в базе, `OutboundResult`, журнале, логах и ответах API.
- `dotnet build LtiIntegrationGateway.slnx` и `dotnet test LtiIntegrationGateway.slnx` проходят;
  новые тесты покрывают успешный mTLS-вызов, отказ без материала и изоляцию обработчиков.
