# Proposal

## Why

Исходящему контуру нужна конфигурация каналов, которой пока нет: `GatewayDbContext` пуст, а
ADR §7 (каналы, авторизация, допустимые пути, политика повторов, неизменяемые ревизии) описан
только на бумаге. Без этого следующий срез (исходящий вызов) нечего исполнять и нечем
ограничивать: нельзя ни проверить допустимость пути, ни взять базовый адрес, ни понять, какая
ревизия активна.

## What Changes

- В `GatewayDbContext` добавляются сущности конфигурации: канал, учётные данные канала
  (тип авторизации и ключ конфигурации, без значений секретов), допустимые методы и шаблоны
  путей, политика повторов, ревизии конфигурации и аудит изменений.
- Добавляются миграции EF Core и применение миграций при старте (SQLite-файл), чтобы схема
  существовала до первого среза, который пишет данные.
- Реализуются вертикальные срезы `Features/Channels`: создание канала (черновик), изменение
  черновика, публикация ревизии, активация ревизии, откат к предыдущей, получение канала с
  активной ревизией.
- Вводится валидация конфигурации: базовый URL — абсолютный `https` без userinfo; методы — из
  фиксированного набора; шаблоны путей — по правилам ADR §8.7; политика повторов — непустой
  список задержек, не более пяти, положительные таймауты, статус-коды в допустимом диапазоне.
- Опубликованная ревизия неизменяема: изменение настроек возможно только через новую ревизию;
  отклонённая публикация не меняет активную конфигурацию и возвращает список причин.
- **BREAKING** для потребителей нет: управляющий API и контракты не меняются.

### Исключения из объёма

- управляющий gRPC/REST API и `.proto` управления каналами (следующий change) — срезы вызываются
  из тестов, HTTP-поверхности пока нет;
- исходящий контур: HTTP-вызовы, операции, журнал сообщений;
- секреты: значения по-прежнему живут в переменных окружения, здесь только ссылка на ключ;
- резолвинг активной ревизии в рантайме с горячей заменой без перезапуска (появится вместе с
  контуром, который её читает);
- продуктовые маршруты (`ProductRoutes`) и OpenAPI-контракты.

### Риски

- **Схема данных зафиксируется раньше, чем появится первый читатель.** Смягчение: модель строится
  строго по ADR §7 и §11.2, а всё, что не описано (например продуктовые маршруты), не добавляется.
- **Миграции при старте приложения.** Принято для SQLite-файла на этом этапе; для промышленной БД
  это пересматривается (ADR §11.1).
- **Политика повторов как документ.** Хранится JSON-документом внутри ревизии: правила
  упорядочены и меняются только вместе с ревизией, отдельная таблица добавила бы риск
  рассинхронизации. Цена — валидация только на стороне приложения.
- **Несовпадение версий `dotnet-ef` (10.0.12) и EF Core (10.0.14).** Проверяется генерацией
  миграции; при проблеме версия инструмента поднимается.

### Проверяемые критерии успеха

- `dotnet build` и `dotnet test` проходят, миграция применяется на пустой базе;
- канал создаётся в состоянии черновика и не является активной конфигурацией;
- публикация ревизии делает её неизменяемой: повторное изменение опубликованных настроек
  отклоняется;
- активация переключает активную ревизию, откат возвращает предыдущую;
- конфигурация с недопустимым базовым URL, методом, шаблоном пути или политикой повторов не
  публикуется, активная ревизия остаётся прежней, причины возвращаются списком;
- в базе нет значений секретов — только тип авторизации и ключ конфигурации.

## Capabilities

### New Capabilities

- `channel-registry`: хранение и публикация конфигурации каналов — черновик, неизменяемая
  ревизия, активация и откат, валидация настроек и отсутствие секретов в хранилище.

### Modified Capabilities

Нет: `gateway-host`, `message-contracts` и `message-serialization` не меняются.

## Impact

- Код: `Infrastructure/Persistence` (модель, конфигурация EF Core, миграции),
  `Features/Channels/*` (срезы), регистрация в `Program.cs` (применение миграций).
- Зависимости: `Microsoft.EntityFrameworkCore.Design` (design-time), существующий
  `Microsoft.EntityFrameworkCore.Sqlite`.
- Тесты: срезы на SQLite `:memory:` с открытым соединением (ADR §11.3), тесты валидации.
- Управляющий API, Rebus, HTTP-контур не затрагиваются.
