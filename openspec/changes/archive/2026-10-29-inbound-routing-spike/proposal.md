# Proposal

## Why

ADR §5.2 выбирает для входящего контура кастомный `EndpointDataSource`, который перестраивается при
активации ревизии контракта, и прямо требует spike до реализации входящего контура: без проверки на
целевой версии .NET нельзя утверждать, что маршруты, добавленные в работающем приложении,
начинают обслуживаться без перезапуска, а endpoint-метаданные (включая ограничение частоты) реально
применяются. Сейчас в шлюзе нет ни входящего контура, ни проверенного механизма динамической
маршрутизации, поэтому вся дальнейшая работа над inbound зависела бы от непроверенного допущения.

## What Changes

- Появляется каталог активных inbound-маршрутов, который позволяет активировать и деактивировать
  набор маршрутов (ревизию) в работающем приложении без перезапуска.
- Появляется источник endpoint'ов, который публикует маршруты каталога как настоящие endpoint'ы
  ASP.NET Core: добавленный маршрут начинает обслуживаться сразу, деактивированный перестаёт
  обслуживаться.
- Активация набора маршрутов проверяется: два маршрута с одинаковыми методом и шаблоном — отказ
  активации, ранее активный набор остаётся в работе.
- Пересекающиеся, но не конфликтующие шаблоны разрешаются детерминированно (запрос всегда попадает
  в один и тот же маршрут).
- Для маршрутов применяется ограничение частоты, привязанное к endpoint и разделяемое по каналу:
  превышение квоты возвращает `429`.
- Динамический endpoint отвечает диагностическим ответом, в котором отражены фактический метод,
  шаблон маршрута и путь запроса — это проверочный probe спайка, а не итоговый контракт входящего
  контура.
- Результат спайка фиксируется в ADR §5.2: подтверждён выбранный механизм или требуется
  зафиксированный fallback.

Исключено из объёма:

- загрузка и версионирование OpenAPI-документов, конвертация Swagger 2.0, отказ для 3.1;
- валидация входящего тела по JSON-схеме (`NJsonSchema`) и перечень поддерживаемых конструкций;
- публикация `InboundMessage` в Rebus, ответы `202`/`503`, дедупликация и обработка ошибок публикации;
- персистентность ревизий контрактов в EF Core и управляющий API для них;
- авторизация входящих вызовов (`api_key`, `basic`, mTLS) — маршруты спайка её не проверяют.

## Capabilities

### New Capabilities

- `inbound-routing`: активация и деактивация набора inbound-маршрутов в работающем приложении,
  обслуживание активных маршрутов и `404` для снятых, детерминированный выбор маршрута при
  пересечении шаблонов, ограничение частоты, привязанное к маршруту и каналу.

### Modified Capabilities

Нет: требования существующих capability (`gateway-host`, `message-contracts`,
`message-serialization`, `channel-registry`, `outbound-dispatch`) не меняются.

## Impact

- Новый код: `Infrastructure/Routing` (определение маршрута, каталог активных наборов, валидатор
  набора, источник endpoint'ов) и `Features/Inbound` (probe-обработчик запроса).
- `Program.cs`: регистрация источника endpoint'ов и ограничителя частоты, `UseRateLimiter`,
  конфигурация лимитов.
- Тесты: `LtiIntegrationGateway.Tests/Features/Inbound` (TUnit + существующая
  `GatewayWebApplicationFactory`).
- Зависимости: только входящие в shared framework ASP.NET Core; новые пакеты не добавляются.
- Протокол Protobuf-контрактов не меняется (`InboundMessage` уже объявлен и в этом change не
  используется).
- База данных не меняется, миграции не требуются.
- ADR `docs/adr/0001-integration-gateway.md` §5.2 дополняется фактическим результатом спайка.

## Критерии успеха

1. Маршрут, активированный после старта приложения, обслуживает запрос без перезапуска.
2. Деактивированный маршрут возвращает `404`.
3. Набор с конфликтом «метод + шаблон» не активируется, активный набор не меняется; пересекающиеся
   шаблоны дают один и тот же маршрут при повторных запросах.
4. Ограничение частоты, заданное на endpoint, реально применяется: превышение квоты → `429`,
   независимые каналы не влияют на квоту друг друга.
5. Все критерии подтверждены интеграционными тестами TUnit, сборка и тесты зелёные.
6. Результат зафиксирован в ADR §5.2 с указанием версии .NET и поведения, которое подтверждено.
