## 5. Интеграционные тесты критериев ADR §5.2

- [x] 5.1 Критерий 1: до активации набора запрос даёт `404`, после активации — `200`, приложение
      не перезапускается
- [x] 5.2 Критерий 2: после деактивации набора его маршрут возвращает `404`
- [x] 5.3 Конфликты: активация набора с дубликатом метода и шаблона отклоняется, ранее активный
      набор продолжает обслуживать запросы; после устранения конфликта набор активируется
- [x] 5.4 Критерий 3: литеральный сегмент выигрывает у параметра, остальные значения обслуживает
      параметрический шаблон, повтор запроса даёт тот же маршрут
- [x] 5.5 Критерий 4: запрос сверх квоты получает `429`, квота другого канала не расходуется,
      после истечения окна запрос снова обслуживается
- [x] 5.6 Статические endpoint'ы не затронуты: при активных динамических маршрутах `/health/live`
      отвечает `200` и не содержит диагностических полей
- [x] 5.7 Критерий 5: все перечисленные сценарии покрыты интеграционными тестами TUnit на
      `WebApplicationFactory<Program>`
