# Spec Delta

## Purpose

Обработка исходящих запросов продукта: проверки перед вызовом, авторизация, HTTP-вызов с
повторами, состояние операции, журнал и доставка результата продукту через Rebus.

## ADDED Requirements

### Requirement: Запрос обрабатывается и результат возвращается продукту

Получив `OutboundRequest`, шлюз SHALL выполнить проверки, при успехе — внешний HTTP-вызов, и SHALL
отправить `OutboundResult` в очередь отправителя. Исход вызова SHALL передаваться в результате, а
не приводить к повтору на уровне шины.

#### Scenario: Успешный вызов

- **WHEN** продукт отправляет валидный запрос по разрешённому каналу
- **THEN** выполняется один HTTP-вызов
- **AND** результат отправляется в очередь отправителя
- **AND** `outcome` равен `HTTP_RESPONSE`

#### Scenario: Внешняя система вернула ошибку

- **WHEN** внешняя система отвечает `500` с телом
- **THEN** результат содержит статус `500` и это тело
- **AND** сообщение не уходит в повтор на уровне шины

### Requirement: Продукт и адрес отправителя проверяются

Шлюз SHALL проверять `product_id` и заголовок `rbs2-sender-address` по конфигурации маршрутов
продуктов. Отсутствие адреса, неизвестный продукт, несоответствие адреса продукту и
неразрешённый канал SHALL приводить к отказу без сетевого вызова.

#### Scenario: Неизвестный продукт

- **WHEN** в запросе указан `product_id`, отсутствующий в конфигурации
- **THEN** результат содержит `outcome = GATEWAY_REFUSED` и код `PRODUCT_NOT_ALLOWED`
- **AND** HTTP-вызов не выполняется

#### Scenario: Адрес не соответствует продукту

- **WHEN** заголовок `rbs2-sender-address` не разрешён для указанного `product_id`
- **THEN** запрос отклоняется с кодом `PRODUCT_NOT_ALLOWED`

#### Scenario: Канал не разрешён продукту

- **WHEN** продукт обращается к каналу, которого нет в его разрешённых каналах
- **THEN** результат содержит код `CHANNEL_NOT_ALLOWED`
- **AND** HTTP-вызов не выполняется

### Requirement: Канал, метод и путь проверяются до вызова

Шлюз SHALL использовать активную ревизию канала. Метод и относительный путь SHALL проверяться:
метод входит в разрешённые, путь проходит структурные запреты и совпадает с одним из шаблонов.
Отсутствие активной ревизии SHALL отклонять запрос.

#### Scenario: У канала нет активной ревизии

- **WHEN** канал существует, но активная ревизия не задана
- **THEN** результат содержит код `CHANNEL_NOT_ACTIVE`
- **AND** HTTP-вызов не выполняется

#### Scenario: Недопустимый путь

- **WHEN** путь содержит `..`, `//`, схему или хост, либо не совпадает с шаблонами канала
- **THEN** результат содержит код `PATH_NOT_ALLOWED`
- **AND** HTTP-вызов не выполняется

#### Scenario: Недопустимый метод

- **WHEN** метод запроса отсутствует в разрешённых методах канала
- **THEN** результат содержит код `METHOD_NOT_ALLOWED`

### Requirement: Авторизация берётся из конфигурации

Значение секрета SHALL браться по ключу конфигурации активной ревизии. Отсутствие значения SHALL
приводить к отказу без вызова. Значения секретов SHALL не попадать в результат, журнал и логи.

#### Scenario: Заголовок авторизации формируется

- **WHEN** канал настроен с типом `bearer` и ключом конфигурации, значение задано
- **THEN** HTTP-запрос содержит заголовок авторизации
- **AND** значение секрета отсутствует в результате и журнале

#### Scenario: Значение секрета отсутствует

- **WHEN** ключ конфигурации задан, но значение в конфигурации отсутствует
- **THEN** результат содержит код `SECRET_NOT_CONFIGURED`
- **AND** HTTP-вызов не выполняется

#### Scenario: Неподдерживаемый тип авторизации

- **WHEN** активная ревизия использует тип `client_certificate`
- **THEN** результат содержит код `AUTH_TYPE_UNSUPPORTED`
- **AND** HTTP-вызов не выполняется

### Requirement: Повторы выполняются по политике канала

Повторы SHALL выполняться для транспортных ошибок и для статусов, указанных в правилах политики,
с задержками из правила. `Retry-After` SHALL учитываться, общий предел длительности SHALL
соблюдаться. `POST` и `PATCH` SHALL повторяться только при непустом `idempotency_key`.

#### Scenario: Повтор при 429

- **WHEN** внешняя система отвечает `429` и правило предусматривает повтор
- **THEN** выполняется повтор после задержки из правила
- **AND** при повторном успехе результат содержит успешный статус

#### Scenario: POST без ключа идемпотентности

- **WHEN** `POST` вернул `503`, а `idempotency_key` не задан
- **THEN** повтор не выполняется
- **AND** результат содержит статус `503`

#### Scenario: Исчерпание повторов

- **WHEN** все попытки завершились транспортной ошибкой
- **THEN** результат содержит `outcome = TRANSPORT_ERROR` и код `RETRIES_EXHAUSTED`
- **AND** число попыток отражено в результате

### Requirement: Повторный запрос не вызывает внешнюю систему

Повторный `OutboundRequest` с тем же `message_id` SHALL не приводить к повторному внешнему вызову:
при завершённой операции возвращается сохранённый результат, при выполняющейся — второй вызов не
запускается. Запрос с чужим `product_id` и тем же `message_id` SHALL отклоняться.

#### Scenario: Повтор после завершения

- **WHEN** приходит запрос с `message_id` завершённой операции
- **THEN** HTTP-вызов не выполняется
- **AND** продукт получает сохранённый результат

#### Scenario: Повтор во время выполнения

- **WHEN** приходит запрос с `message_id` выполняющейся операции
- **THEN** второй HTTP-вызов не выполняется

#### Scenario: Чужой продукт

- **WHEN** приходит запрос с `message_id` другого продукта
- **THEN** результат содержит код `PRODUCT_NOT_ALLOWED`
- **AND** сохранённый результат другому продукту не отдаётся

### Requirement: Операция и журнал фиксируются

До попытки доставки результата шлюз SHALL сохранить состояние операции и запись журнала с телами
запроса и ответа, статусом, исходом, числом попыток и адресом доставки. Признак доставки SHALL
меняться на «отправлено» после успешной отправки.

#### Scenario: Запись после вызова

- **WHEN** вызов завершён
- **THEN** операция находится в состоянии завершённой
- **AND** журнал содержит тело запроса и тело ответа
- **AND** признак доставки отражает факт отправки результата
