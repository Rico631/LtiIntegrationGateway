# Spec Delta

## ADDED Requirements

### Requirement: Проблемы несут severity

Каждый `OperationProblem` SHALL содержать `severity`: `ERROR` для отказа и `WARNING` для
предупреждения. `ContractOperationResponse` SHALL NOT иметь отдельного списка `warnings`:
предупреждения передаются в `problems` с `severity = WARNING`, а `succeeded` отражает результат
операции.

#### Scenario: Отказ

- **WHEN** управляющая команда отклонена проверкой
- **THEN** её проблемы имеют `severity = ERROR`
- **AND** `succeeded = false`

#### Scenario: Предупреждение

- **WHEN** операция выполнена, но есть замечание (например, отсутствует секрет канала)
- **THEN** `succeeded = true`
- **AND** предупреждение присутствует в `problems` с `severity = WARNING`

### Requirement: Обязательные поля команд проверяются

Management-команды SHALL проверять обязательные поля запроса до бизнес-логики. Пустое обязательное
поле SHALL давать проблему с `severity = ERROR` и `succeeded = false`. Методы чтения SHALL сохранять
текущее поведение: пустое имя канала или версии возвращает `NotFound`.

#### Scenario: Пустое имя канала

- **WHEN** команда создания, изменения, публикации, активации или отката получает пустое имя канала
- **THEN** ответ содержит проблему `severity = ERROR` с кодом поля
- **AND** `succeeded = false`
- **AND** срез не вызывается

#### Scenario: Пустое имя в чтении

- **WHEN** запрос чтения канала содержит пустое имя
- **THEN** ответ имеет статус `404` (`NotFound`)

## MODIFIED Requirements

### Requirement: Настройки операции доступны через управляющий API

Управляющий API SHALL отдавать настройки каждой операции версии контракта (`enabled` и
переопределение очереди) и SHALL позволять изменять их для версии, кроме `superseded`. Изменение
настроек активной версии SHALL применяться к работающим маршрутам без перезапуска. Неизвестная
версия или операция SHALL возвращать `404` (`NotFound`). Операции без `operationId` в документе
управляющим API не адресуются: чтобы менять их настройки, контракт должен задавать `operationId`.

#### Scenario: Чтение настроек операции

- **WHEN** запрашиваются операции версии контракта
- **THEN** каждая операция содержит `enabled` и переопределение очереди
- **AND** отсутствие переопределения выражается пустой строкой

#### Scenario: Изменение настроек опубликованной версии

- **WHEN** для операции опубликованной версии задаются `enabled = false` и собственная очередь
- **THEN** операция завершается успешно
- **AND** повторное чтение возвращает новые значения

#### Scenario: Изменение настроек активной операции

- **WHEN** для операции активной версии задаётся `enabled = false`
- **THEN** операция завершается успешно
- **AND** последующий вызов этой операции получает `404` без перезапуска приложения

#### Scenario: Переопределение квоты

- **WHEN** запрашивается переопределение квоты на операции
- **THEN** настройка не поддерживается
- **AND** применяется квота версии контракта или общая квота приложения

#### Scenario: Отменённая версия

- **WHEN** настройки операции изменяются для версии `superseded`
- **THEN** ответ содержит проблему `version`
- **AND** настройки не меняются

#### Scenario: Неизвестная операция

- **WHEN** запрашивается изменение операции, которой нет в версии
- **THEN** ответ имеет статус `404` (`NotFound`)

#### Scenario: Операция без operationId

- **WHEN** операция документа объявлена без `operationId`
- **THEN** её настройки недоступны через управляющий API
- **AND** запрос изменения возвращает `404` (`NotFound`)

#### Scenario: Изменение попадает в аудит

- **WHEN** настройки операции изменяются через управляющий API
- **THEN** аудит содержит операцию, канал, версию, `operationId` и результат
- **AND** значения секретов в аудите отсутствуют
