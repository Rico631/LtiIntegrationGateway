# Spec Delta

## ADDED Requirements

### Requirement: Настройки операции управляются отдельно от версии контракта

Операция контракта SHALL хранить признак `enabled`, переопределение очереди получателя и
переопределение квоты частоты. Действующая очередь и квота SHALL определяться переопределением
операции, а при его отсутствии — настройками версии контракта. Настройки операции SHALL изменяться
без изменения OpenAPI-документа и без перезапуска приложения; настройки отменённой версии изменять
нельзя.

#### Scenario: Переопределение очереди

- **WHEN** у операции задана очередь получателя, отличная от очереди версии
- **THEN** вызовы этой операции передаются в очередь операции
- **AND** вызовы других операций этой версии продолжают использовать очередь версии

#### Scenario: Переопределение квоты

- **WHEN** у операции задана квота, отличная от квоты версии
- **THEN** к операции применяется квота операции
- **AND** квота версии действует для остальных её операций

#### Scenario: Изменение отменённой версии

- **WHEN** настройки операции изменяются для версии в состоянии `superseded`
- **THEN** операция отклоняется с проблемой `version`
- **AND** настройки не меняются

## MODIFIED Requirements

### Requirement: Публикация версии извлекает операции и проверяет конфликты

Публикация версии SHALL создавать неизменяемую ревизию контракта с операциями (HTTP-метод, шаблон
пути, `operationId`, схемы тела по каждому объявленному `Content-Type`) и SHALL отклоняться при
повторяющемся `operationId`, конфликте шаблонов маршрутов с активной конфигурацией или отсутствии
очереди получателя в настройках версии.

#### Scenario: Успешная публикация

- **WHEN** публикуется версия с операцией `GET /callbacks/contracts/{id}`
- **THEN** ревизия содержит операцию с этим методом и шаблоном
- **AND** операция доступна для чтения через API

#### Scenario: Схема тела сохранена

- **WHEN** операция объявляет тело `application/json` со схемой, содержащей локальные `$ref`
- **THEN** схема сохраняется в ревизии в самодостаточном виде
- **AND** при приёме вызова тело проверяется по этой схеме

#### Scenario: Повторяющийся operationId

- **WHEN** в документе две операции с `operationId: receiveContract`
- **THEN** публикация отклоняется с указанием повторяющегося `operationId`

#### Scenario: Конфликт шаблонов

- **WHEN** публикуемая версия содержит маршрут, совпадающий по методу и шаблону с активным маршрутом другой ревизии
- **THEN** публикация отклоняется с указанием конфликта

#### Scenario: Очередь получателя не задана

- **WHEN** в настройках версии отсутствует очередь получателя
- **THEN** публикация отклоняется
- **AND** ревизия не создаётся

#### Scenario: Включённая операция без очереди

- **WHEN** операция включена, не имеет собственной очереди, а у версии очередь не задана
- **THEN** публикация отклоняется с проблемой `queue`
- **AND** ревизия не создаётся

#### Scenario: Все операции отключены

- **WHEN** все операции версии отключены, а очередь получателя задана
- **THEN** публикация допускается
- **AND** ни одна операция не обслуживает вызовы после активации версии

#### Scenario: Перенос настроек операции

- **WHEN** публикуется новая версия, содержащая операцию с тем же `operationId`, методом и шаблоном,
  что и предыдущая версия
- **THEN** настройки операции (`enabled`, очередь, квота) переносятся из предыдущей версии
- **AND** для новой операции применяются значения по умолчанию

#### Scenario: Перенос без operationId

- **WHEN** у операции предыдущей или новой версии `operationId` отсутствует, а метод и шаблон совпадают
- **THEN** настройки переносятся по паре «метод + шаблон»

#### Scenario: operationId изменился

- **WHEN** у операции изменился `operationId` при том же методе и шаблоне
- **THEN** настройки не переносятся
- **AND** применяются значения по умолчанию
