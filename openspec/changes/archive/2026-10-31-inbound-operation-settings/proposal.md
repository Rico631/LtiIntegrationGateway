# Proposal

## Why

ADR §7.3 требует, чтобы маршрут создавался для каждой операции контракта, а настройки операции
(`enabled`, очередь получателя, лимит частоты) переопределяли настройки контракта и могли меняться
без перезапуска. Сейчас настройки задаются только на версии контракта: включить или отключить
отдельную операцию, направить её в другую очередь или задать отдельную квоту нельзя. Отключённая
операция из ADR §13 (ответ `404` с записью в аудит) не реализована, перенос настроек при публикации
новой версии отсутствует, а управляющий API (ADR §15.2) не предоставляет `PATCH` настроек операции.

## What Changes

- У операции контракта появляются собственные настройки: признак `enabled`, переопределение очереди
  получателя и переопределение квоты частоты. Действующее значение = переопределение операции, иначе
  значение версии контракта.
- Публикация версии отклоняется, если включённая операция не имеет действующей очереди получателя
  (код `queue`); при публикации новой версии настройки переносятся по совпадению `operationId`,
  HTTP-метода и шаблона пути, для новых операций действуют значения по умолчанию.
- Отключённая операция не обслуживает вызовы: ответ `404`, при этом событие фиксируется в аудите с
  указанием, что путь известен, но операция отключена (ADR §13).
- Управляющий API получает операцию изменения настроек операции
  (`PATCH /v1/channels/{channel}/contracts/{version}/operations/{operationId}`) и отдаёт настройки в
  чтении версии и списке операций. Изменение настроек активной версии применяется без перезапуска;
  настройки отменённой (`superseded`) версии изменить нельзя.
- Ограничение частоты применяется к маршруту по действующей квоте операции; ключ ограничения
  остаётся каналом.

Исключено из объёма:

- HMAC-подпись входящих вызовов — отдельное решение (ADR §7.3);
- дедупликация входящих событий — не выполняется (ADR §10.3);
- персональная идентичность администратора управляющего API — открытый вопрос ADR §20;
- изменение самого OpenAPI-документа опубликованной версии — документ остаётся неизменяемым.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `contract-registry`: настройки операции, проверка очереди при публикации, перенос настроек между
  версиями.
- `inbound-routing`: действующая очередь и квота операции, отключённая операция отвечает `404` и
  фиксируется в аудите.
- `management-api`: чтение и изменение настроек операции через gRPC и REST.

## Impact

- `Protos/v1/management_api.proto` — поля настроек операции и новый RPC с HTTP-аннотацией.
- `Infrastructure/Persistence` — сущность `ContractOperation`, миграция.
- `Features/Contracts` — публикация, активация, чтение операций, новый срез изменения настроек,
  построение набора маршрутов.
- `Infrastructure/Routing` — маршрут с действующими настройками, endpoint отключённой операции.
- `Features/Management` — фасад нового RPC, маппинг.
- `src/LtiIntegrationGateway.Tests` — тесты публикации, настроек, маршрутов, аудита, квоты.
- `README.md`, `ARCHITECTURE.md` — фактическое описание настроек операции.

## Assumptions

- Настройки операции — изменяемый слой поверх неизменяемого документа версии: сам документ и набор
  операций не меняются, поэтому требование ADR §15.3 о неизменяемости опубликованной ревизии
  сохраняется. Это уточнение фиксируется в design и спеках.
- Аудит отключённой операции пишется в существующую таблицу `ManagementAuditEntries` с операцией
  `InboundOperationDisabled`: отдельная таблица аудита входящих вызовов не вводится.
- `operationId` не обязателен в OpenAPI; адресация настроек операции использует `operationId`, поэтому
  операции без него управляющим API не адресуются (ответ `404`) — это известное ограничение,
  зафиксированное в README. Перенос настроек выполняется по `operationId` при совпадении метода и
  шаблона; если `operationId` отсутствует хотя бы у одной из операций — по паре «метод + шаблон».

## Risks

- Изменение настроек активной версии затрагивает работающий каталог маршрутов: при ошибке
  перерегистрации необходимо восстановить предыдущий набор, иначе часть маршрутов перестанет
  обслуживаться.
- Одновременное изменение настроек и активация версии могут конкурировать; координация
  распределённой блокировкой не реализуется (ADR §12, §20), конфликт разрешается повтором операции.

## Success Criteria

- Включённая операция без действующей очереди не публикуется (код `queue`); отключённая операция
  публикуется без очереди.
- `PATCH` настроек операции меняет `enabled`, очередь и квоту; изменение активно для работающих
  маршрутов без перезапуска.
- Отключённая операция отвечает `404`, в аудите есть запись с указанием причины.
- Действующая квота операции переопределяет квоту контракта; ключ ограничения — канал.
- Настройки переносятся в новую версию по `operationId` + методу + шаблону.
- `dotnet build` и `dotnet test` проходят; сценарии покрыты тестами.
