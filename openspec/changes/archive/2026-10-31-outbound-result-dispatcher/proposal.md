# Proposal

## Why

ADR §8.9 задаёт гарантию «минимум один раз» для `OutboundResult`: результат фиксируется в журнале со
статусом `pending` до попытки отправки, а недоставленные записи повторно отправляет фоновый
диспетчер. Сейчас шаг диспетчера отсутствует: если `Send` не удался, запись навсегда остаётся в
`pending`, и продукт не получает результат — единственный экземпляр результата потерян.

Одновременно ADR §8.10 требует, чтобы повторный `OutboundRequest` с тем же `message_id` возвращал
**тот же** результат. Текущее повторение собирает результат из состояния операции и теряет тело
ответа, `Content-Type`, `error_message` и `correlation_id`, поэтому повтор не идентичен первому.

## What Changes

- Журнал `OutboundMessageLog` получает адрес доставки и `error_message`; операция — `correlation_id`.
  Эти поля нужны, чтобы восстановить результат в исходном виде после перезапуска процесса.
- Добавляется индекс по признаку доставки: диспетчер читает только записи `pending`.
- Появляется фоновый диспетчер: периодически читает `pending`-записи, восстанавливает `OutboundResult`
  из сохранённых данных, отправляет его по сохранённому адресу и помечает запись `sent`. Ошибка
  отправки оставляет запись `pending` для следующей попытки.
- Повторный `OutboundRequest` с завершённым `message_id` отдаёт результат, восстановленный из
  журнала: тело, `Content-Type`, код и текст ошибки, число попыток и `correlation_id` совпадают с
  первым результатом (ADR §8.10).
- Параметры диспетчера (включение, интервал, размер пачки) задаются конфигурацией; в тестах хост
  по умолчанию диспетчер не запускает.
- Гарантия остаётся «минимум один раз»: дубли допустимы, продукт дедуплицирует по `message_id`.

Исключено из объёма:

- распределённая блокировка и координация нескольких экземпляров шлюза — открытый вопрос ADR §12,
  §20; диспетчер рассчитан на один экземпляр, дубли при масштабировании допустимы;
- промышленный транспорт Rebus и пересмотр схемы доставки — открытый вопрос ADR §20;
- политика хранения журнала и очистка записей — ADR §11.2 фиксирует бессрочное хранение;
- ручной запуск повторной доставки через управляющий API — не требуется ADR.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `outbound-dispatch`: результат фиксируется с адресом доставки; недоставленные результаты повторно
  отправляются диспетчером; повторный запрос возвращает идентичный сохранённый результат.

## Impact

- `src/LtiIntegrationGateway/Infrastructure/Persistence` — сущности `OutboundMessageLog`,
  `OutboundOperation`, конфигурация индекса, миграция.
- `src/LtiIntegrationGateway/Features/Outbound` — запись журнала, восстановление результата, новый
  фоновый диспетчер.
- `Program.cs`, `appsettings.json` — регистрация и параметры диспетчера.
- `src/LtiIntegrationGateway.Tests` — тесты восстановления результата, диспетчера и повторов.
- `README.md`, `ARCHITECTURE.md` — описание диспетчера и ограничений.

## Assumptions

- Диспетчер работает в одном экземпляре приложения; при нескольких экземплярах возможны дубли,
  что соответствует гарантии «минимум один раз» и не требует распределённой блокировки.
- Интервал и размер пачки — эксплуатационные параметры; значения по умолчанию выбираются
  консервативно (15 секунд, 50 записей) и не являются частью контракта.

## Risks

- На in-memory-транспорте получатель очереди не переживает рестарт: запись помечается `sent`, хотя
  продукт может не получить сообщение. Это ограничение транспорта (ADR §10.1), а не диспетчера.
- Фоновая служба в тестовом хосте может мешать детерминированности; в тестовой конфигурации она
  выключена по умолчанию.

## Success Criteria

- Запись журнала со статусом `pending` повторно отправляется диспетчером и переходит в `sent`.
- Запись `sent` повторно не отправляется.
- Ошибка повторной отправки оставляет запись `pending` и не роняет приложение.
- Повторный `OutboundRequest` возвращает результат, идентичный первому по телу, статусу,
  `Content-Type`, коду и тексту ошибки, числу попыток и `correlation_id`.
- `dotnet build` и `dotnet test` проходят; новые сценарии покрыты тестами.
