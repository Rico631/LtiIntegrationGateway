# Spec Delta

## MODIFIED Requirements

### Requirement: Отсутствие демонстрационного API

Хост `Management` SHALL публиковать только управляющий API и health-пробы. Хост `Flow` SHALL
публиковать только динамические входящие маршруты, health-пробы и диагностику применённой
конфигурации. Управляющий API SHALL быть недоступен в `Flow`. Демонстрационные эндпоинты отсутствуют
в обоих сервисах.

#### Scenario: Обращение к шаблонному эндпоинту

- **WHEN** клиент выполняет `GET /weatherforecast`
- **THEN** хост отвечает `404 Not Found`
- **AND** в приложении нет обработчика, зарегистрированного под этот путь

#### Scenario: Управляющий API недоступен в сервисе потоков

- **WHEN** клиент выполняет `GET /v1/integrations/bank-a/outbound-channels` на хосте `Flow`
- **THEN** ответ имеет статус `404`
- **AND** управляющие операции недоступны и через gRPC

#### Scenario: Список доступных путей после старта

- **WHEN** приложение запущено с конфигурацией по умолчанию
- **THEN** среди путей `Management` доступны управляющий API и health-пробы
- **AND** среди путей `Flow` доступны health-пробы и диагностика конфигурации
- **AND** шаблонных путей демонстрационного API нет

### Requirement: Обязательная конфигурация хранилища

Оба сервиса SHALL требовать строку подключения хранилища в конфигурации. При её отсутствии запуск
SHALL завершаться ошибкой с указанием отсутствующего ключа конфигурации.

#### Scenario: Запуск без строки подключения

- **WHEN** приложение запускается, а ключ `ConnectionStrings:Gateway` не задан
- **THEN** запуск завершается ошибкой
- **AND** сообщение об ошибке содержит имя отсутствующего ключа
- **AND** приложение не начинает обслуживать запросы

#### Scenario: Запуск с заданной строкой подключения

- **WHEN** ключ `ConnectionStrings:Gateway` содержит корректную строку подключения PostgreSQL
- **THEN** приложение запускается и обслуживает запросы
- **AND** хранилище доступно сценариям, которым оно потребуется

### Requirement: Секреты активной конфигурации проверяются при старте

Перед началом обслуживания запросов `Management` SHALL проверять секреты всех активных ревизий
каналов и активных версий контрактов. `Flow` SHALL проверять секреты активной конфигурации своей
интеграции. Для типов авторизации, требующих секрет, отсутствие значения или непригодный материал
клиентского сертификата SHALL завершать запуск ошибкой с перечнем имён ключей конфигурации без
значений. Конфигурации вне состояния `Active` SHALL NOT блокировать запуск.

#### Scenario: Секрет отсутствует

- **WHEN** активная ревизия канала требует секрет, а значение по ключу конфигурации отсутствует
- **THEN** запуск завершается ошибкой
- **AND** сообщение содержит имя ключа без значения
- **AND** сервис не начинает обслуживать запросы

#### Scenario: Все секреты настроены

- **WHEN** все активные ревизии и версии контрактов обеспечены секретами
- **THEN** запуск продолжается
- **AND** сервис обслуживает запросы

#### Scenario: Черновик без секрета

- **WHEN** черновик канала или версии контракта не имеет секрета
- **THEN** запуск не блокируется

#### Scenario: Секрет другой интеграции

- **WHEN** `Flow` интеграции `bank-a` запускается, а секрет требуется только конфигурацией `bank-b`
- **THEN** запуск `bank-a` не блокируется этим секретом
- **AND** проблема фиксируется при проверке в `Management`

## ADDED Requirements

### Requirement: Схемой хранилища владеет только сервис управления

Миграции схемы хранилища SHALL применяться только сервисом `Management`. Сервис `Flow` SHALL NOT
изменять схему хранилища. При несовместимой схеме запуск `Flow` SHALL завершаться ошибкой.

#### Scenario: Запуск сервиса потоков

- **WHEN** `Flow` запускается при уже применённой схеме
- **THEN** миграции не выполняются
- **AND** сервис обслуживает запросы

#### Scenario: Несовместимая схема

- **WHEN** `Flow` запускается, а схема хранилища не соответствует ожидаемой
- **THEN** запуск завершается ошибкой
- **AND** схема хранилища не изменяется
