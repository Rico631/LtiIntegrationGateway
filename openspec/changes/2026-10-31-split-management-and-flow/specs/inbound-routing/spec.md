# Spec Delta

## MODIFIED Requirements

### Requirement: Набор маршрутов активируется без перезапуска приложения

Экземпляр сервиса потоков SHALL принимать действующий набор входящих маршрутов своей интеграции без
перезапуска и SHALL обслуживать запросы по нему не позднее 5 секунд после фиксации изменения.
Деактивация набора SHALL прекращать обслуживание его маршрутов: запросы к ним SHALL получать `404`.

#### Scenario: Активация нового маршрута

- **WHEN** после старта экземпляра активируется набор с маршрутом `GET /callbacks/contracts/{id}/status`
- **THEN** запрос `GET /callbacks/contracts/42/status` обслуживается не позднее 5 секунд
- **AND** ответ имеет статус, определённый правилами приёма входящего вызова (`202` при передаче
  продукту; `200` для входящих вызовов не используется)

#### Scenario: Деактивация набора

- **WHEN** активный набор маршрутов деактивируется
- **THEN** запрос к пути из этого набора получает `404` после применения конфигурации

#### Scenario: Неизвестный путь

- **WHEN** запрошен путь, отсутствующий во всех активных наборах интеграции
- **THEN** ответ имеет статус `404`

#### Scenario: Маршрут другой интеграции

- **WHEN** запрошен путь, активный только в наборе другой интеграции
- **THEN** ответ имеет статус `404`
- **AND** маршрут другой интеграции не регистрируется в этом экземпляре

### Requirement: Конфликтующие маршруты не активируются

Активация набора SHALL отклоняться, если два маршрута набора совпадают по методу и шаблону, если
маршрут набора конфликтует с уже активным маршрутом другого набора той же интеграции, или если метод
маршрута не поддерживается. Отклонённая активация SHALL не изменять состав активных маршрутов.

#### Scenario: Конфликт внутри набора

- **WHEN** набор содержит два маршрута `POST /callbacks/contracts`
- **THEN** активация отклоняется
- **AND** в отказе указаны конфликтующие метод и шаблон

#### Scenario: Конфликт с активным маршрутом другой ревизии

- **WHEN** активируется набор с маршрутом `GET /callbacks/orders/{id}`, который уже активен в другом
  наборе той же интеграции
- **THEN** активация отклоняется
- **AND** ранее активный маршрут продолжает обслуживать запросы

#### Scenario: Совпадение с маршрутом другой интеграции

- **WHEN** активируется набор интеграции `bank-a` с маршрутом, активным в `bank-b`
- **THEN** активация выполняется успешно
- **AND** маршрут `bank-b` продолжает обслуживать запросы своего экземпляра

#### Scenario: Неподдерживаемый метод

- **WHEN** набор содержит маршрут с методом `TRACE`
- **THEN** активация отклоняется

#### Scenario: Активация после устранения конфликта

- **WHEN** конфликтующий маршрут удалён из набора и набор активируется повторно
- **THEN** набор активируется и его маршруты обслуживают запросы

### Requirement: Ограничение частоты применяется к маршруту

Для входящего маршрута SHALL применяться ограничение частоты, разделяемое по каналу: запросы сверх
квоты SHALL получать `429`, а квота одного канала SHALL не расходоваться запросами другого канала.
Квота SHALL браться из настроек активной ревизии контракта, а при их отсутствии — из общих настроек
приложения. Ключ ограничения — канал; операции одного канала используют общий бюджет. Бюджет SHALL
действовать в пределах экземпляра сервиса потоков.

#### Scenario: Превышение квоты

- **WHEN** количество запросов к маршруту за окно превышает заданную квоту
- **THEN** запрос сверх квоты получает `429`

#### Scenario: Квота берётся из настроек ревизии

- **WHEN** ревизия контракта задаёт собственную квоту, отличную от общей
- **THEN** применяется квота ревизии

#### Scenario: Квота операции не переопределяет версию

- **WHEN** запрашивается изменение квоты операции
- **THEN** настройка не поддерживается
- **AND** действует квота версии контракта

#### Scenario: Независимость каналов

- **WHEN** квота канала `bank-a` исчерпана
- **THEN** запрос по маршруту канала `bank-b` по-прежнему обслуживается со статусом `202`

#### Scenario: Две реплики

- **WHEN** экземпляр интеграции исчерпал квоту канала
- **THEN** запросы, попавшие на другую реплику, обслуживаются в пределах её собственного бюджета
- **AND** суммарный бюджет интеграции равен сумме бюджетов реплик

#### Scenario: Восстановление квоты

- **WHEN** окно квоты истекло
- **THEN** запрос к маршруту снова обслуживается со статусом `202`
