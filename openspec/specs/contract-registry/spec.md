# contract-registry Specification

## Purpose

Версии OpenAPI-контрактов входящих интеграций: загрузка и fail-closed проверка документа, публикация
ревизии с операциями, активация ревизии с регистрацией входящих маршрутов и неизменяемость
опубликованных ревизий.

## Requirements

### Requirement: Загрузка документа создаёт черновик версии контракта

Создание `InboundChannel` SHALL требовать OpenAPI-документ и SHALL создавать черновик версии
контракта 1. Последующие загрузки документа в существующий `InboundChannel` SHALL создавать
следующую версию в состоянии черновика. Исходный документ SHALL сохраняться без изменений; OpenAPI
3.0 SHALL приниматься как есть, Swagger 2.0 SHALL приниматься с конвертацией в 3.0 и фиксацией факта
конвертации в аудите, OpenAPI 3.1 SHALL отклоняться.

#### Scenario: Создание inbound-канала с документом

- **WHEN** создаётся `InboundChannel` с корректным OpenAPI-документом
- **THEN** создаётся канал и черновик версии контракта 1
- **AND** endpoints канала не активны до публикации и активации

#### Scenario: Новая версия существующего канала

- **WHEN** для существующего `InboundChannel` загружается новый OpenAPI-документ
- **THEN** создаётся следующая версия контракта в состоянии черновика
- **AND** активная версия и её endpoints не меняются

#### Scenario: Документ OpenAPI 3.0

- **WHEN** загружается документ `openapi: 3.0.x`
- **THEN** создаётся версия контракта в состоянии черновика
- **AND** сохранённый документ совпадает с загруженным

#### Scenario: Документ Swagger 2.0

- **WHEN** загружается документ `swagger: "2.0"`
- **THEN** версия создаётся
- **AND** аудит содержит запись о конвертации в 3.0

#### Scenario: Документ OpenAPI 3.1

- **WHEN** загружается документ `openapi: 3.1.0`
- **THEN** загрузка отклоняется
- **AND** ответ содержит проблему с указанием неподдерживаемой версии

### Requirement: Проверка документа выполняется по принципу fail-closed

Загрузка SHALL отклоняться, если документ содержит конструкции вне поддерживаемого перечня или
ссылки, кроме локальных. Отказ SHALL возвращать полный список проблем с путями до элементов.
Неизвестный `format` SHALL не отклонять документ, а попадать в предупреждения.

#### Scenario: Запрещённые конструкции

- **WHEN** документ содержит ключевое слово `if` или `unevaluatedProperties` в схеме
- **THEN** загрузка отклоняется
- **AND** ответ содержит проблему с путём до этой схемы

#### Scenario: Внешняя ссылка

- **WHEN** документ содержит `$ref` на `https://example.com/schema.json`
- **THEN** загрузка отклоняется с указанием запрещённой ссылки

#### Scenario: Поля рядом с `$ref`

- **WHEN** документ содержит `{ "$ref": "#/components/schemas/X", "nullable": true }`
- **THEN** загрузка отклоняется с указанием на сочетание полей

#### Scenario: Неизвестный format

- **WHEN** документ содержит `format: "bank-account"`
- **THEN** версия создаётся
- **AND** ответ содержит предупреждение о неизвестном `format`

#### Scenario: Несколько проблем

- **WHEN** документ содержит внешнюю ссылку и запрещённую конструкцию
- **THEN** ответ содержит обе проблемы

### Requirement: Версия контракта содержит настройки входящих вызовов

Версия контракта SHALL хранить настройки входящих вызовов: очередь получателя, тип авторизации и её
несекретные параметры (имя заголовка, имя пользователя, ключ конфигурации), а также квоту частоты.
Настройки SHALL изменяться только пока версия находится в состоянии черновика. Значения секретов
SHALL не храниться.

#### Scenario: Настройки сохранены в черновике

- **WHEN** для черновика версии задаются очередь получателя, тип авторизации `api_key`, имя заголовка
  и ключ конфигурации
- **THEN** настройки сохраняются
- **AND** повторное чтение версии возвращает эти значения

#### Scenario: Изменение опубликованной версии

- **WHEN** настройки изменяются для опубликованной или активной версии
- **THEN** операция отклоняется
- **AND** действующие настройки не меняются

#### Scenario: Значения секретов не хранятся

- **WHEN** задаётся ключ конфигурации секрета
- **THEN** в базе хранится только ключ
- **AND** значение секрета в ответах API отсутствует

### Requirement: Публикация версии извлекает операции и проверяет конфликты

Публикация версии SHALL создавать неизменяемую ревизию контракта с операциями (HTTP-метод, шаблон
пути, `operationId`, схемы тела по каждому объявленному `Content-Type`) и SHALL отклоняться при
повторяющемся `operationId`, конфликте шаблонов маршрутов с активной конфигурацией или отсутствии
очереди получателя в настройках версии.

#### Scenario: Успешная публикация

- **WHEN** публикуется версия с операцией `GET /callbacks/contracts/{id}`
- **THEN** ревизия содержит операцию с этим методом и шаблоном
- **AND** операция доступна для чтения через API

#### Scenario: Схема тела сохранена

- **WHEN** операция объявляет тело `application/json` со схемой, содержащей локальные `$ref`
- **THEN** схема сохраняется в ревизии в самодостаточном виде
- **AND** при приёме вызова тело проверяется по этой схеме

#### Scenario: Повторяющийся operationId

- **WHEN** в документе две операции с `operationId: receiveContract`
- **THEN** публикация отклоняется с указанием повторяющегося `operationId`

#### Scenario: Конфликт шаблонов

- **WHEN** публикуемая версия содержит маршрут, совпадающий по методу и шаблону с активным маршрутом другой ревизии
- **THEN** публикация отклоняется с указанием конфликта

#### Scenario: Очередь получателя не задана

- **WHEN** в настройках версии отсутствует очередь получателя
- **THEN** публикация отклоняется
- **AND** ревизия не создаётся

#### Scenario: Включённая операция без очереди

- **WHEN** операция включена, не имеет собственной очереди, а у версии очередь не задана
- **THEN** публикация отклоняется с проблемой `queue`
- **AND** ревизия не создаётся

#### Scenario: Все операции отключены

- **WHEN** все операции версии отключены, а очередь получателя задана
- **THEN** публикация допускается
- **AND** ни одна операция не обслуживает вызовы после активации версии

#### Scenario: Перенос настроек операции

- **WHEN** публикуется новая версия, содержащая операцию с тем же `operationId`, методом и шаблоном,
  что и предыдущая версия
- **THEN** настройки операции (`enabled`, очередь) переносятся из предыдущей версии
- **AND** для новой операции применяются значения по умолчанию

#### Scenario: Перенос без operationId

- **WHEN** у операции предыдущей или новой версии `operationId` отсутствует, а метод и шаблон совпадают
- **THEN** настройки переносятся по паре «метод + шаблон»

#### Scenario: operationId изменился

- **WHEN** у операции изменился `operationId` при том же методе и шаблоне
- **THEN** настройки не переносятся
- **AND** применяются значения по умолчанию

### Requirement: Активация ревизии регистрирует входящие маршруты

Активация ревизии контракта SHALL делать маршруты этой ревизии обслуживаемыми и SHALL снимать
маршруты ранее активной ревизии. Одновременно SHALL быть активна только одна ревизия контракта.

#### Scenario: Активация новой ревизии

- **WHEN** активируется ревизия с операцией `POST /callbacks/contracts`
- **THEN** запрос `POST /callbacks/contracts` обслуживается
- **AND** активной считается эта ревизия

#### Scenario: Снятие предыдущих маршрутов

- **WHEN** активируется новая ревизия, в которой операции `POST /callbacks/contracts` больше нет
- **THEN** запрос `POST /callbacks/contracts` получает `404`

#### Scenario: Отказ при конфликте

- **WHEN** активируемая ревизия конфликтует с активными маршрутами другого контракта
- **THEN** активация отклоняется
- **AND** ранее активные маршруты продолжают обслуживаться

### Requirement: Опубликованная ревизия неизменяема

Опубликованная и активированная ревизия контракта SHALL не изменяться. Изменение документа SHALL
выполняться загрузкой новой версии; состояние активной ревизии при этом SHALL сохраняться до
активации новой.

#### Scenario: Повторная загрузка

- **WHEN** после активации ревизии загружается изменённый документ
- **THEN** создаётся новая версия в состоянии черновика
- **AND** активная ревизия и её маршруты не меняются

#### Scenario: Попытка изменить опубликованную версию

- **WHEN** для опубликованной версии запрашивается изменение документа
- **THEN** операция отклоняется

### Requirement: Настройки операции управляются отдельно от версии контракта

Операция контракта SHALL хранить признак `enabled` и переопределение очереди получателя. Действующая
очередь SHALL определяться переопределением операции, а при его отсутствии — настройками версии
контракта. Квота частоты SHALL задаваться только на версии контракта. Настройки операции SHALL
изменяться без изменения OpenAPI-документа и без перезапуска приложения; настройки отменённой
версии изменять нельзя.

#### Scenario: Переопределение очереди

- **WHEN** у операции задана очередь получателя, отличная от очереди версии
- **THEN** вызовы этой операции передаются в очередь операции
- **AND** вызовы других операций этой версии продолжают использовать очередь версии

#### Scenario: Переопределение квоты

- **WHEN** запрашивается изменение квоты операции
- **THEN** настройка не поддерживается
- **AND** для всех операций действует квота версии

#### Scenario: Изменение отменённой версии

- **WHEN** настройки операции изменяются для версии в состоянии `superseded`
- **THEN** операция отклоняется с проблемой `version`
- **AND** настройки не меняются

### Requirement: Очередь получателя соответствует имени очереди продукта

Очередь получателя версии контракта SHALL иметь формат `<product_id>.inbox`, где `product_id`
соответствует `^[a-z][a-z0-9-]{1,31}$`. Публикация версии с очередью другого формата SHALL
отклоняться с проблемой `queue`.

#### Scenario: Корректная очередь

- **WHEN** публикуется версия с очередью `dpv.inbox`
- **THEN** публикация проходит проверку очереди

#### Scenario: Некорректная очередь

- **WHEN** публикуется версия с очередью `inbound.queue`
- **THEN** публикация отклоняется с проблемой `queue`
- **AND** операции версии не создаются

### Requirement: Контракт принадлежит только InboundChannel

Версия контракта SHALL принадлежать только `InboundChannel`, а её операции SHALL использоваться
для построения входящих маршрутов этого канала. Контракт SHALL NOT принадлежать outbound-каналу.

#### Scenario: Загрузка документа в outbound-канал

- **WHEN** документ загружается для outbound-канала
- **THEN** операция отклоняется
- **AND** версия контракта не создаётся

#### Scenario: Операции принадлежат inbound-каналу

- **WHEN** версия `InboundChannel` активируется
- **THEN** её операции регистрируются как входящие маршруты этого канала
- **AND** outbound-маршруты и ревизии не затрагиваются
