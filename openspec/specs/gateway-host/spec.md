# gateway-host Specification

## Purpose

Поведение хоста шлюза: что приложение предоставляет при запуске, чего в нём быть не должно, и
какие требования предъявляются к его конфигурации до появления интеграционных сценариев.

## Requirements

### Requirement: Отсутствие демонстрационного API

Хост шлюза SHALL публиковать только эндпоинты, относящиеся к функциональности шлюза, включая
health-пробы. Эндпоинты, добавленные генератором проекта, в приложении отсутствуют.

#### Scenario: Обращение к шаблонному эндпоинту

- **WHEN** клиент выполняет `GET /weatherforecast`
- **THEN** хост отвечает `404 Not Found`
- **AND** в приложении нет обработчика, зарегистрированного под этот путь

#### Scenario: Список доступных путей после старта

- **WHEN** приложение запущено с конфигурацией по умолчанию
- **THEN** среди health-путей доступны только liveness- и readiness-пробы
- **AND** шаблонных путей демонстрационного API нет

### Requirement: Liveness-проба

Хост SHALL предоставлять пробу живучести по пути `GET /health/live`. Проба SHALL возвращать
`200` без обращений к базе данных, Rebus и внешним системам, чтобы оставаться пригодной при
недоступности зависимостей.

#### Scenario: Успешная проба живучести

- **WHEN** клиент выполняет `GET /health/live`
- **THEN** хост отвечает `200 OK`
- **AND** тело ответа содержит признак состояния без подробностей конфигурации

#### Scenario: Проба при ненастроенных зависимостях

- **WHEN** приложение запущено без настроек Rebus, каналов и внешних систем
- **THEN** `GET /health/live` отвечает `200 OK`
- **AND** проба не выполняет сетевых вызовов

### Requirement: Readiness-проба

Хост SHALL предоставлять пробу готовности по пути `GET /health/ready`. Проба SHALL проверять
доступность хранилища и возвращать `200` при успехе и `503` при недоступности зависимости, не
раскрывая параметров подключения и секретов.

#### Scenario: Хранилище доступно

- **WHEN** клиент выполняет `GET /health/ready`, а хранилище отвечает
- **THEN** хост отвечает `200 OK`
- **AND** тело ответа сообщает о готовности без деталей конфигурации

#### Scenario: Хранилище недоступно

- **WHEN** клиент выполняет `GET /health/ready`, а проверка хранилища завершается ошибкой
- **THEN** хост отвечает `503 Service Unavailable`
- **AND** тело ответа не содержит строки подключения и секретов

#### Scenario: Liveness не зависит от readiness

- **WHEN** проверка хранилища завершается ошибкой
- **THEN** `GET /health/live` по-прежнему отвечает `200 OK`
- **AND** liveness не выполняет обращений к хранилищу

### Requirement: Обязательная конфигурация хранилища

Приложение SHALL требовать строку подключения хранилища в конфигурации. При её отсутствии
запуск SHALL завершаться ошибкой с указанием отсутствующего ключа конфигурации.

#### Scenario: Запуск без строки подключения

- **WHEN** приложение запускается, а ключ `ConnectionStrings:Gateway` не задан
- **THEN** запуск завершается ошибкой
- **AND** сообщение об ошибке содержит имя отсутствующего ключа
- **AND** приложение не начинает обслуживать запросы

#### Scenario: Запуск с заданной строкой подключения

- **WHEN** ключ `ConnectionStrings:Gateway` содержит корректную строку подключения SQLite
- **THEN** приложение запускается и обслуживает запросы
- **AND** хранилище доступно сценариям, которым оно потребуется

### Requirement: Секреты активной конфигурации проверяются при старте

Перед началом обслуживания запросов шлюз SHALL проверять секреты всех активных ревизий каналов и
активных версий контрактов. Для типов авторизации, требующих секрет, отсутствие значения или
непригодный материал клиентского сертификата SHALL завершать запуск ошибкой с перечнем имён ключей
конфигурации без значений. Конфигурации вне состояния `Active` SHALL NOT блокировать запуск.

#### Scenario: Секрет отсутствует

- **WHEN** активная ревизия канала требует секрет, а значение по ключу конфигурации отсутствует
- **THEN** запуск завершается ошибкой
- **AND** сообщение содержит имя ключа без значения
- **AND** шлюз не начинает обслуживать запросы

#### Scenario: Все секреты настроены

- **WHEN** все активные ревизии и версии контрактов обеспечены секретами
- **THEN** запуск продолжается
- **AND** шлюз обслуживает запросы

#### Scenario: Черновик без секрета

- **WHEN** черновик канала или версии контракта не имеет секрета
- **THEN** запуск не блокируется

### Requirement: Отсутствие секретов в логах запуска

Логи запуска приложения SHALL не содержать значений строки подключения и других секретов
конфигурации.

#### Scenario: Старт с заданной строкой подключения

- **WHEN** приложение стартует с заполненным ключом `ConnectionStrings:Gateway`
- **THEN** записи лога запуска не содержат значения строки подключения
- **AND** сообщение об успешном старте не раскрывает параметров подключения
