# inbound-routing Specification

## Purpose

Динамические входящие HTTP-маршруты шлюза: активация и деактивация набора маршрутов в работающем
приложении, детерминированный выбор маршрута при пересечении шаблонов и ограничение частоты,
привязанное к маршруту и каналу.

## Requirements

### Requirement: Набор маршрутов активируется без перезапуска приложения

Шлюз SHALL принимать набор входящих маршрутов в работающем приложении и SHALL обслуживать запросы
по активированным маршрутам без перезапуска. Деактивация набора SHALL прекращать обслуживание его
маршрутов: запросы к ним SHALL получать `404`.

#### Scenario: Активация нового маршрута

- **WHEN** после старта приложения активируется набор с маршрутом `GET /callbacks/contracts/{id}/status`
- **THEN** запрос `GET /callbacks/contracts/42/status` обслуживается без перезапуска приложения
- **AND** ответ имеет статус `200`

#### Scenario: Деактивация набора

- **WHEN** активный набор маршрутов деактивируется
- **THEN** запрос к пути из этого набора получает `404`

#### Scenario: Неизвестный путь

- **WHEN** запрошен путь, отсутствующий во всех активных наборах
- **THEN** ответ имеет статус `404`

### Requirement: Конфликтующие маршруты не активируются

Активация набора SHALL отклоняться, если два маршрута набора совпадают по методу и шаблону, если
маршрут набора конфликтует с уже активным маршрутом другого набора, или если метод маршрута
не поддерживается. Отклонённая активация SHALL не изменять состав активных маршрутов.

#### Scenario: Конфликт внутри набора

- **WHEN** набор содержит два маршрута `POST /callbacks/contracts`
- **THEN** активация отклоняется
- **AND** в отказе указаны конфликтующие метод и шаблон

#### Scenario: Конфликт с активным маршрутом другой ревизии

- **WHEN** активируется набор с маршрутом `GET /callbacks/orders/{id}`, который уже активен в другом наборе
- **THEN** активация отклоняется
- **AND** ранее активный маршрут продолжает обслуживать запросы

#### Scenario: Неподдерживаемый метод

- **WHEN** набор содержит маршрут с методом `TRACE`
- **THEN** активация отклоняется

#### Scenario: Активация после устранения конфликта

- **WHEN** конфликтующий маршрут удалён из набора и набор активируется повторно
- **THEN** набор активируется и его маршруты обслуживают запросы

### Requirement: Пересекающиеся шаблоны разрешаются детерминированно

Если активные шаблоны пересекаются, маршрут SHALL выбираться по одному и тому же правилу для
каждого запроса: литеральный сегмент имеет приоритет над параметрическим.

#### Scenario: Литеральный сегмент важнее параметра

- **WHEN** активны маршруты `GET /callbacks/{name}` и `GET /callbacks/health`
- **THEN** запрос `GET /callbacks/health` обслуживается маршрутом `GET /callbacks/health`

#### Scenario: Параметр обслуживает остальные значения

- **WHEN** активны те же маршруты и запрошен `GET /callbacks/payments`
- **THEN** запрос обслуживается маршрутом `GET /callbacks/{name}`

#### Scenario: Повторный запрос не меняет маршрут

- **WHEN** один и тот же запрос повторяется несколько раз
- **THEN** каждый раз выбирается один и тот же маршрут

### Requirement: Ограничение частоты применяется к маршруту

Для входящего маршрута SHALL применяться ограничение частоты, разделяемое по каналу: запросы сверх
квоты SHALL получать `429`, а квота одного канала SHALL не расходоваться запросами другого канала.

#### Scenario: Превышение квоты

- **WHEN** количество запросов к маршруту за окно превышает заданную квоту
- **THEN** запрос сверх квоты получает `429`

#### Scenario: Независимость каналов

- **WHEN** квота канала `bank-a` исчерпана
- **THEN** запрос по маршруту канала `bank-b` по-прежнему обслуживается со статусом `200`

#### Scenario: Восстановление квоты

- **WHEN** окно квоты истекло
- **THEN** запрос к маршруту снова обслуживается со статусом `200`

### Requirement: Диагностический ответ подтверждает выбранный маршрут

Динамический endpoint SHALL отвечать `200` и возвращать фактические метод, шаблон маршрута,
относительный путь и имя канала. Передача входящих сообщений в шину в рамках этого изменения
SHALL не выполняться: обработчик маршрута не публикует сообщения.

#### Scenario: Состав ответа

- **WHEN** запрос обслужен динамическим маршрутом
- **THEN** ответ содержит HTTP-метод, шаблон маршрута, относительный путь и имя канала

#### Scenario: Статические endpoint'ы не затронуты

- **WHEN** в приложении активны динамические маршруты
- **THEN** запрос `/health/live` по-прежнему обслуживается статическим endpoint'ом
- **AND** его ответ не содержит диагностических полей динамического маршрута
