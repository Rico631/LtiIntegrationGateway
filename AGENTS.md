# AGENTS.md

Правила для агентов, работающих в репозитории `LtiIntegrationGateway`.

## Источники контекста и документации

Перед началом работы используй следующие источники по их назначению:

- `openspec/config.yaml` — правила подготовки и сопровождения артефактов OpenSpec.
- `openspec/specs/` — актуальные функциональные и системные требования, ожидаемое поведение и проверяемые сценарии. Перед изменением изучай затрагиваемые спецификации.
- `ARCHITECTURE.md` — архитектурные границы, принципы, технические ограничения, взаимодействия компонентов и фактическая организация решения.
- `src/LtiIntegrationGateway/Protos/` — исходные контракты gRPC/REST и сообщений Rebus.
- `README.md` — обзор проекта, настройка, сборка и запуск.
- `openspec/changes/` и `openspec/changes/archive/` — контекст и история текущих и завершённых изменений.

Не создавай ADR и не поддерживай отдельный журнал архитектурных решений. Контекст, альтернативы и причины конкретного изменения фиксируй в OpenSpec Change; после принятия изменения актуализируй соответствующие Specs и, когда затронута архитектура, `ARCHITECTURE.md`. Не дублируй в OpenSpec полные архитектурные ограничения из `ARCHITECTURE.md`.

## C#: только primary constructor

**Требование.** Параметры создания типа SHALL объявляться в primary constructor — в заголовке `class` или `struct`. Явный конструктор с телом, единственная задача которого — присвоить параметры полям, запрещён. Поля-копии зависимостей (например, `private readonly GatewayDbContext _db;`) не создаются: вместо них используется захваченный параметр primary constructor.

Правило действует для производственного кода и тестов в `src/**`, кроме сгенерированного кода.

## Контракты Protobuf: обязательная документация

Protobuf-файлы — единственный публикуемый артефакт контракта: потребитель забирает `.proto` из репозитория и генерирует типы самостоятельно. Поэтому комментарии в `.proto` являются нормативной документацией контракта.

**Требование.** Каждый файл `src/LtiIntegrationGateway/Protos/**/*.proto`, кроме вендорных копий `Protos/google/api/**` (их не редактировать), SHALL быть документирован полностью. Комментарий обязателен непосредственно перед каждым:

- `service`;
- `rpc`;
- `message`;
- `enum` и каждым значением `enum`;
- каждым полем сообщения.

Объявления и поля без комментария не принимаются. Это блокирующий дефект, а не замечание к стилю.

### Состав документации

- **Шапка файла:** назначение пакета, способы доступа (gRPC и/или REST), аутентификация, правила ошибок, требования совместимости, обращение с секретами.
- **`service`:** назначение сервиса, его потребители и общие правила для всех методов.
- **`rpc`:** назначение операции, семантика параметров, поведение при отказе и отсутствии объекта, итоговый REST-маршрут при использовании `google.api.http`.
- **`message`:** назначение сообщения, кто его заполняет, какие поля обязательны по смыслу.
- **`enum` и значения:** смысл каждого значения; отдельно — значение нулевого элемента.
- **Поле:** смысл, формат и допустимые значения, единицы измерения, трактовка пустой строки и нуля, ограничения (уникальность, длина, диапазон), источник значения.

### Дополнительные правила

- Комментарии пишутся только через `//` непосредственно перед объявлением. `protoc` переносит их в XML-документацию сгенерированных типов, поэтому они доступны потребителям в IDE.
- Язык комментариев — русский; имена типов, полей, методов, пакетов и файлов — английский.
- Значения секретов в комментариях не приводятся: описываются только ключи конфигурации и правила их использования.
- При изменении семантики поля комментарий обновляется в том же изменении, что и контракт.
- Удалённое поле помечается `reserved` по номеру и имени; рядом указывается причина.
- Номера полей никогда не переиспользуются. Порядок и типы опубликованных полей не меняются несовместимым образом в существующей версии контракта; для несовместимых изменений создаётся новый `package` (`v2`).

### Проверка документации `.proto`

Запусти из корня репозитория в PowerShell:

```powershell
$files = Get-ChildItem -Recurse 'src\LtiIntegrationGateway\Protos' -Filter '*.proto' -File |
    Where-Object { $_.FullName -notmatch '[\\/]google[\\/]api[\\/]' }

$issues = foreach ($file in $files) {
    $lines = Get-Content $file
    for ($i = 0; $i -lt $lines.Count; $i++) {
        $line = $lines[$i].Trim()
        $isDocumentedDeclaration =
            $line -match '^(message|service|enum)\s+' -or
            $line -match '^rpc\s+' -or
            $line -match '^(?:(optional|required|repeated)\s+)?(?:[\w.]+|map\s*<[^>]+>)\s+\w+\s*=\s*\d+\s*;' -or
            $line -match '^\w+\s*=\s*-?\d+\s*;' -or
            $line -match '^reserved\s+'

        if ($isDocumentedDeclaration -and ($i -eq 0 -or -not $lines[$i - 1].Trim().StartsWith('//'))) {
            "{0}:{1}: отсутствует комментарий перед: {2}" -f $file.FullName, ($i + 1), $line
        }
    }
}

if ($issues) {
    $issues
    throw 'Обнаружены объявления Protobuf без обязательной документации.'
}

'documentation check: OK'
```

Проверка должна завершиться сообщением `documentation check: OK` без перечня нарушений. Затем выполни:

```powershell
dotnet build LtiIntegrationGateway.slnx
```

Сборка должна завершиться без ошибок и предупреждений. Не объявляй проверку или сборку успешной, если команда фактически не запускалась или завершилась ошибкой.

## C#: обработчики и сущности

### Обработчики

Файл, содержащий тип с суффиксом `Handler`, SHALL называться `<ИмяТипа>.cs`. Например, `LoadActiveChannelHandler` хранится в `LoadActiveChannelHandler.cs`.

### Сущности

- Файлы в `Infrastructure/Persistence/Entities/**` SHALL быть сгруппированы по логическим папкам: `Channels`, `Contracts`, `Inbound`, `Outbound`, `ProductRoutes`, `Management`.
- Каждый класс сущности SHALL реализовывать `IEntity`.
- Каждое публичное свойство сущности SHALL иметь XML-комментарий `<summary>`.
- Перечисления, относящиеся к сущностям, документируются аналогично.

### Результаты операций

Если операция возвращает значение и допускает отказ, используй `Infrastructure/Results/Result<T>` с полями `Value`, `ErrorCode`, `ErrorMessage`. Не создавай отдельные типы-результаты с тем же набором полей без обоснованной необходимости.
