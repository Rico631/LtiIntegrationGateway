# AGENTS.md

Правила для агентов, работающих в репозитории `LtiIntegrationGateway`.

Контекст проекта и технологические ограничения — `openspec/config.yaml`; архитектурные решения —
`docs/adr/0001-integration-gateway.md`; текущие требования — `openspec/specs/`.

## C#: только primary constructor

**Требование.** Параметры создания типа SHALL объявляться в primary constructor — в заголовке `class`
или `struct`. Явный конструктор с телом, единственная задача которого — присвоить параметры полям,
запрещён: поля-копии (`private readonly GatewayDbContext _db;`) не создаются, вместо них используется
захваченный параметр primary constructor. Правило действует и для производственного кода, и для
тестов (`src/**`, кроме сгенерированного).

## Контракты Protobuf: обязательная документация

Protobuf-файлы — единственный публикуемый артефакт контракта: потребитель забирает `.proto` из
репозитория и генерирует типы сам, поэтому документация в них нормативна, а не вспомогательна.

**Требование.** Каждый файл `src/LtiIntegrationGateway/Protos/**/*.proto` (кроме вендорных копий
`Protos/google/api/**`, которые не редактируются) SHALL быть документирован полностью: комментарий
обязателен перед каждым `service`, `rpc`, `message`, `enum`, значением `enum` и перед каждым полем
сообщения. Объявления и поля без комментария в контракт не принимаются — это блокирующий дефект,
а не замечание к стилю.

Состав документации:

- **Шапка файла:** назначение пакета, способы доступа (gRPC и/или REST), аутентификация, правила
  ошибок, требования совместимости, обращение с секретами.
- **`service`:** что за сервис, кто потребитель, какие общие правила действуют для всех методов.
- **`rpc`:** что делает операция, семантика параметров, поведение при отказе и отсутствии объекта,
  итоговый REST-маршрут при использовании `google.api.http`.
- **`message`:** когда используется, кто заполняет, какие поля обязательны по смыслу.
- **`enum` и его значения:** смысл каждого значения; отдельно — что означает значение `0`.
- **Поле:** смысл, формат и допустимые значения, единицы измерения, трактовка пустой строки и нуля,
  ограничения (уникальность, длина, диапазон), источник значения.

Дополнительные правила:

- комментарии — только `//` непосредственно перед объявлением: protoc переносит их в XML-документацию
  сгенерированных типов, поэтому они видны потребителю в IDE;
- язык комментариев — русский; имена типов, полей, методов и файлов — английские;
- значения секретов в комментариях не приводятся: описываются только ключи конфигурации и правила
  их использования;
- при изменении семантики поля комментарий обновляется в том же изменении, что и контракт;
- удалённое поле помечается `reserved` (по номеру и имени) с комментарием причины;
- номера полей не переиспользуются, порядок и типы полей не меняются без нового `package` (`v2`).

Проверка перед сдачей изменения:

```powershell
# каждое объявление и поле должны иметь комментарий в предыдущей строке
$files = Get-ChildItem -Recurse 'src\LtiIntegrationGateway\Protos' -Filter *.proto |
    Where-Object { $_.FullName -notmatch '\\google\\api\\' }
foreach ($f in $files) {
    $lines = Get-Content $f
    for ($i = 0; $i -lt $lines.Count; $i++) {
        $line = $lines[$i].Trim()
        if ($line -match '^(message|service|enum)\s' -or $line -match '^rpc\s' -or
            $line -match '^(repeated\s+)?[\w\.]+\s+\w+\s*=\s*\d+;') {
            if (-not $lines[$i - 1].Trim().StartsWith('//')) { "$($f.Name):$($i + 1): $line" }
        }
    }
}
```

Вывод команды должен быть пустым; сборка `dotnet build LtiIntegrationGateway.slnx` — без ошибок и
предупреждений.
